# Контракт «код ↔ дизайн»

Код подхватывает вашу карту и модели автоматически, если соблюдены имена ниже.
Пока чего-то нет — код работает: монстры спавнятся фиолетовыми плейсхолдерами, телепорты пропускаются.

## Карта (Workspace)

```
Workspace/
  HubSpawn            — Part: точка возврата в хаб после визита
  Plots/              — папка с 8 участками
    Plot1..Plot8      — Model, каждый:
      Entrance        — Part: куда телепортируется посетитель
      Slots/          — папка точек аттракционов
        Slot1..Slot10 — Part: точка спавна монстра/аттракциона
```

- Имена слотов строго `Slot1`, `Slot2`… — код ищет `Slot{номер}`.
- Части-точки можно делать невидимыми (`Transparency = 1`), но НЕ удалять.
- Код сам ставит атрибут `OwnerUserId` на занятый участок — можно использовать для табличек «Парк игрока X».

## Модели монстров (ServerStorage)

```
ServerStorage/
  MonsterModels/
    boo_balloon       — Model (имя = id из src/shared/MonsterCatalog.luau)
    intern_skeleton
    …
```

- У модели должен быть PrimaryPart (или хотя бы один BasePart — код возьмёт первый).
- id всех 15 монстров — в `src/shared/MonsterCatalog.luau`, колонка `id`.
- Анимации (idle/скример/погоня) добавим отдельным полем каталога, когда появятся.

## Чекпоинты аттракционов (позже, Этап 2)

Прогресс прохождения (0..1) сейчас двигается через `ScareService.SetProgress`.
Когда появятся аттракционы: части с тегом `Checkpoint` и атрибутом `Progress` (число 0..1) —
Touched-обработчик добавим в код, от дизайна нужны только сами части с тегом.

## Звуки

Скример-звуки: положить в модель монстра `Sound` с именем `ScreamSound` — клиентский
эффект (`VisitUI.playScareEffect`) начнёт их проигрывать, когда договоримся о формате.
Помни: звук — 60% испуга (00-design-doc §10.3).
